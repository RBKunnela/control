Changelog

Notable changes to this project are recorded here. The format follows Keep a Changelog, and the project uses semantic versioning.

The 0.x series carries no compatibility promise between minor versions; see ADR-0008. Each release is built, signed and attested from its tag; RELEASING.md shows how to verify one.

Unreleased

0.12.0 - 2026-10-16

The experimental enforcement API gets an experimental Python client, guardana_control.enforce. Once this release is published, the release workflow uploads it to PyPI as guardana-control by trusted publishing (ADR-0053). It asks a plane for a decision before your tool acts and reports how the call ended. It cooperates and is not a security boundary, and it passes the same conformance cases and answer vectors as the Go reference. Each change now reaches main through a pull request that must pass CI's make quality (ADR-0052). Among the fixes from a code audit: on Linux the enforcement receiver no longer removes a socket a live receiver may hold, supervision reports a deadline not checked when an event of the run has no timestamp, and react reads the clock for each stop as it writes it. The project is still alpha, and the 0.x series makes no compatibility promise between minor versions.

Added

  • A Python client of the experimental enforcement API, under clients/python/ and imported as guardana_control.enforce (ADR-0053). One synchronous call asks the plane, runs your tool only with the bytes it authorized, and closes with one complete or one abort. It imports the standard library alone and needs Python 3.11 or later. It cooperates and is not a boundary: its calls are decided, not enforced.
  • Answer vectors in testdata/enforce/answers/vectors.jsonl: a status and a body with what a client must do with it. Each is read, refused, or may_refuse, where the Go reference reads a form outside the one the receiver writes and another client may refuse it. The Go reference, a second Go client and the Python client run them, and they seed the decoder's fuzz target. docs/contracts.md says which form a client may rely on.
  • One more client case, tool-reports-nothing: a tool that returns without a status is completed UNKNOWN.
  • make check-python, part of make quality: the client's tests on two pinned CPython versions, its linter and type checker, and a build of its wheel. make bootstrap installs uv and both interpreters.
  • The release workflow builds the Python client's wheel and source archive and attests them before any other tool of the release job runs. After the GitHub release is published, a separate job in the pypi environment waits for a maintainer's approval, then uploads exactly the files the build listed to PyPI by trusted publishing, with no stored token, and reads the index back. The dry run uploads a development release to TestPyPI the same way, from main.

Changed

  • A change reaches main as one squash-merged pull request whose gate is CI's make quality, a maintainer's own included; only a release commit is still gated cold on a maintainer's machine and pushed directly. Until 1.0 a release follows every one to three changes (ADR-0052).
  • The race tests run every night with every processor busy, on Linux and on macOS, so a test that depends on the clock fails there and not in a release gate. A red night opens an issue.
  • The README, the site's title and the repository's description call the project an AI agent supervision framework; the README opens with what runs today and puts the 1.0 goal after it.
  • scripts/pre-push.sh asks for a gate stamp for commits sent to main and for the commit a v* tag names, and for nothing else: a branch push needs none. A main the remote does not hold yet counts every commit. The hook has a negative control, make pre-push-probe, in make quality.

Fixed

  • The enforcement receiver removes a socket left at its path only when a connection to it is refused. A timeout, a full backlog on Linux or a permission error refuses the start with ErrSocketInUse and leaves the socket of a receiver that may still be live. On macOS a live receiver whose backlog is full refuses connections too, so a second plane started then can still take its path.
  • supervise reports DEADLINE_EXCEEDED not checked when an event of the run has no time and the timed events stay within deadline_seconds; it was reported checked on a span that may have been longer. A breach on the timed events still fires; under a 0.2 procedure the rule is then checked for the tree, and a run whose events have no time gets no finding.
  • react reads the clock for each stop it writes. A pass that ran longer than a rule's lifetime wrote a stop that had already expired, counted the finding as stopped, and never stopped the run for it again.
  • examples/evidence-report -state holds a finding or a policy reload linked after a request's end to the request's enforcement mode, as the one-shot report does: an undeclared or other mode is lifecycle_unknown. Its state.json is now 1.1 and keeps each ended request's mode; a 1.0 state is still read, and an annotation after the end of a request it holds is unknown, since its mode was not kept.
  • The gateway's configuration reader keeps a double-quoted value whole when it holds an escaped quote: "a\" #b" was cut at the # as a comment and the file refused.

0.11.0 - 2026-10-12

A tool outside MCP can now ask for a decision before it acts and report how the call ended, through the experimental enforcement API (ADR-0051). The same policy, approvals and trail apply as to an MCP call. A reference client and conformance cases that a client in another language can run come with it. REPEATED_DENIAL is version 2, which needs a signed route upgrade (see Changed). Fixes from a code audit bound several waits and refuse records another account could rewrite. From this release a version is a plain X.Y.Z without the -alpha suffix (ADR-0025); the project is still alpha, and the 0.x series still makes no compatibility promise between minor versions.

Added

  • The enforcement API contract, guardana.control.enforce.v1alpha1: the admit, complete and abort messages a tool outside MCP exchanges with the plane as JSON over HTTP on a Unix socket (ADR-0051). Unstable and outside the v1 promise; buf breaking does not compare it.
  • guardana-gateway run serves it under listener.kind: enforce_api, with listener.socket, listener.execution_lifetime (1s to 1h, no default), listener.max_body_bytes (1 KiB to 256 KiB, default 128 KiB), listener.max_open_per_run (default 16, below approvals.max_open) and a tools table that classifies each tool by name. Such a plane needs runs.dir and refuses upstreams, overrides and the keys only an MCP listener reads; an MCP listener refuses the new keys. A sweep abandons expired handles. A stop abandons every open execution before the spool drains. /healthz reports the adapter's counts under enforce, and doctor checks an enforcement API plane. A guide shows a tool of your own decided through it.
  • adapters/enforce, its adapter, builds a tool's envelope from the run token and the operator's tool table. A handle is single use and expires. The adapter refuses a duplicate request key, closes an expired execution as abandoned and limits a run's open executions. It blocks a rewrite that moves the decided resource, and answers RECORDED only once the closing record is written. It declares cooperative enforcement and reads a resource and a run token the way the MCP adapter does (internal/adapterkit).
  • internal/enforceclient, the reference client, runs a tool only with the bytes an EXECUTE answer authorized. It aborts on an obligation it does not know, completes UNKNOWN when the tool cannot tell how the call ended, and never sends a request twice. testdata/enforce/ holds the client and the receiver conformance cases, each with a negative control.
  • The coverage inventory kind enforce_tool: a tool an enforcement API plane classifies is "decided, not enforced" in every mode, since a cooperating client, not the plane, keeps it from its effect.
  • The pipeline can close an execution nobody completed or aborted as failed, with result unknown and the new reason code EXECUTION_ABANDONED. It never closes one as a success and does not halt the plane for it. A byte mismatch a client reports through a cooperating adapter blocks only that run's material calls until flow.max_runs runs are halted; past that, and through an inline adapter, a mismatch halts the plane's material calls. Metrics count them: pipeline_runs_halted, pipeline_abandoned_total, pipeline_sink_failures_abandoned_total, pipeline_halted_mismatch and pipeline_halted_sink.
  • Control and supervision explains the 1.0 goal and what the alpha does today: observation across connected channels, procedure checks and reactions within scoped authority. It keeps the AuthZEN, enforcement and operator API roles apart. Backlog task B28 plans continuous supervision.
  • Planned requirements (B23–B27, proposed ADR-0050): previewing MCP setup, qualifying coding-agent hooks, reviewing tool-definition changes, simulating candidate policies and reviewing findings with an incident export. None is built.

Changed

  • On an enforce_api plane /metrics writes the enforcement API adapter's counts (enforce_*) and the flag listener_enforce_api, and leaves out the MCP adapter's adapter_* metrics. doctor checks the socket's directory as run does, and judges pause entries against the tool table.
  • approvals.max_held_per_run (default 16, only with runs.dir, below approvals.max_held) bounds one run's held requests; an expired hold no longer counts against its run. A configuration with runs.dir and an approvals.max_held of 16 or less no longer loads until approvals.max_held_per_run is set below it. A tool's provider and resource_type are bounded at 1024 bytes. Under policy.fail_open_read an enforce_tool line says a read runs undecided while the policy is unavailable.
  • The configuration loader refuses a tool name over 1024 bytes, a resource_from the adapters refuse, and a socket path over 103 bytes.
  • examples/evidence-report reports a timeout or unknown outcome as uncertain, not failed, exits 1 on it, and raises effect_uncertain.
  • REPEATED_DENIAL is version 2. When some denials it would cite are in doubt (a broken chain or an event id read with two contents), it cites only the clean ones and stays CONFIRMED if at least max_denials are clean; otherwise nothing changes. Its finding ids change with the version. route sign, react, the stops writers and a plane refuse a route naming rule_version "1". To upgrade, set it to "2", raise the route's serial and sign it, run stops init --route <new> --public-key <file> --carry <old dir> --carry-route <old route> <new dir>, point reaction.route, reaction.stops and react at the new route and list, and restart the plane. The carry keeps every unlifted stop, at version 1. A lifted run whose denials still meet the rule is stopped again by its version 2 finding, which has another id, and is lifted again. Only --carry-route reads the old version.
  • The adapter capability Block is now Enforcement: none, cooperative or inline. ENFORCE, APPROVE and LOCKDOWN need at least a cooperating adapter, and the MCP adapter is inline; doctor and the modes table name cooperative and inline enforcement apart.
  • Two approvals from the security maintainers now cover every file ADR-0008 says the gate is built from (all of scripts/ and .github/, the Makefile, the linter and buf configurations, go.mod and go.sum) and the gateway's wiring of its decision point, adapter, approvals and stop. A test holds the declaration to the record's list.
  • README and the home page show exact-action approval, changed tool definitions and a denied refund retried through another tool, with their coverage limits and links to the policies and runnable example.
  • README, the home page and the social card lead with observing agents and controlling how they act. The 1.0 goal is marked planned beside what the alpha does, and the declared repository description says the same.

Fixed

  • scripts/github-settings-check.sh and the bootstrap, run by macOS's bash 3.2 on a loaded machine, could build a declared ruleset as nothing and report it unknown: bash 3.2 fails a builtin's write to a pipe that a child's exit interrupts ("printf: write error: Interrupted system call"). The declarations are now printed through cat, which nothing interrupts.
  • /healthz could show the spool drained while the exporter's acknowledged count did not yet include what it had released, since it read the exporter first and the exporter counted a release after making it. On a loaded machine guardana-gateway scenario run then failed a foreign trail file with the wrong reason. The spool is now read first, and a release is counted under the lock the exporter's counters are read under.
  • guardana-control notify could count a delivered alert as failed with "killing the program's process group: operation not permitted". On a loaded macOS host the kernel can refuse the program's group with EPERM for a moment after its leader was reaped. It is now asked again for up to a second; a group still refused after that is reported as before.
  • Opening a findings log, an observation log or a trail file cut a torn last line by the length read before the file was locked. When a second writer opened the same file, cut the tail and committed a write between the first one reading the length and taking the lock, the first then truncated that committed write. Open now reads the length and judges the file again once it holds the lock.
  • The records, markers, state and lock files under an approvals, a runs and a hold journal directory were read when a group or the world could write them, and all but the hold journal's also when another account owned them. An account with write access to such a file could rewrite it in place, granting an approval, extending a run or washing a root clean. Each is now refused as a file that is not the directory's.
  • A hold journal entry was read whatever schema version its approval carried. An approval of another major, or with none, now leaves the entry unreadable.
  • Closing an approvals handle while a call ran on it was a data race on whether the handle was open.
  • A pause, a stop or a halt that came while an opened run's root was being raised was missed, and the call was recorded as started anyway. The plane now checks them again after a raise that wrote, and a halt raised after admission also blocks a material call before a resume spends its approval and before it starts.
  • One opened run can hold at most 16 requests for approval, so it cannot fill approvals.max_held for every other run; a hold past that is blocked EVIDENCE_UNAVAILABLE, like one past approvals.max_held.
  • /healthz names only the plane's own halts: a mismatch that halted one run no longer sets halt.executed_args_mismatch, and halt.evidence_unwritable is set beside it when both stand.
  • A client's abort whose record the sink refused counts as a lost closing record, so run exits 1, as a lost completion did.
  • make quality runs every check even when make is told one is up to date (-o, --old-file, or either in MAKEFLAGS or GNUMAKEFLAGS), and refuses a MAKE or GO from the environment, any command-line variable but GO=go, -e, a FUZZTIME or RANGE from the environment, a makefile read beside the Makefile, and an --eval or -E string for any target; its second make starts with none of the first's flags, and CI clears make's flag variables before running it.
  • The test report refuses a passing package in which a test started and never reported a result, as when the test ends the process with exit status 0. A test that writes its own pass before it exits still hides the tests after it; review catches that.
  • The documentation checks read the commit's own file list in a gate-commit export instead of a walk that skips dot-directories.
  • The release gate refuses a commit that is not main's head, and refuses unless main's newest CodeQL analysis is of the commit being released.
  • guardana-gateway waited at start, with no listener bound, on an upstream that took the connection and never answered its initialization. The connect is now bounded by upstream.list_timeout, and the configuration reference says so.
  • runs open, runs close, runs list and supervise --runs waited without a bound for another operator command's lock while opening the directory; their ten-second bound now covers the open too.
  • supervise read a request whose events name two runs as one run's request. Such a request is now in doubt and confirms nothing.
  • A floor store that stopped answering kept one call per policy poll waiting in the background; calls to it now take turns, so at most one waits.
  • A raise of a policy floor could wait out its deadline while reads of the same floor directory in the same process ran back to back, since each read took the lock again before the raise next tried. Reads that start while a raise of the process waits now go after it; across processes the lock still favours no one.

0.10.2-alpha - 2026-10-10

Fixes and release tooling from an outside audit of 0.10.0-alpha, with no new feature: react no longer times a whole pass by its lock wait, the release scans every binary it ships before attesting it, the website names the published release rather than the next one, the repository's GitHub settings have a read-only check, and a pause file replaced during a read is read again. 0.10.1-alpha was tagged with most of these changes and never published: its release job stopped at the new image scan.

Added

  • The release scans every binary it ships before anything is attested or published: each binary of every archive and the image's binary for linux/amd64 and linux/arm64, with govulncheck in binary mode (scripts/scan-binaries.sh). A known vulnerability, or a scan that could not run, stops the release; the dry run scans its archives and image too.
  • An issue template for a report from trying it with your own MCP client and server.
  • docs/reference/versions.md lists every format a user writes or reads with the version this release writes, the versions it reads and its stability, held to the code's constants by a test. The wire contract's 1.0 is the one stable format; the product is still 0.x.

Changed

  • The website names the published release, which docs/docs.json sets once a release is out, rather than the newest dated section of this file, and each page's footer links that release's documentation at its tag (ADR-0049). The site had named 0.10.0-alpha a day before it was published.
  • The home page leads with what runs today, a gateway that decides MCP tool calls, states what it does not cover, and says what each planned task brings. It no longer says the product watches by default: the enforcement mode has no default (ADR-0032).
  • The repository's GitHub settings are declared once, in scripts/lib/github-settings.sh: scripts/github-bootstrap.sh applies them, and scripts/github-settings-check.sh compares them with GitHub without writing (rulesets, required checks, bypasses, who holds maintain or admin, labels and milestones), exiting 1 on drift and 2 when something could not be read. Two approvals and code-owner review now also cover adapters/authzen/ and adapters/mcp/; the paths are spread over rulesets of at most 15 patterns each, GitHub's limit per reviewer, which the bootstrap checks before it writes anything. Milestones follow the roadmap, and labels use GitHub's good first issue and help wanted.
  • CI's quality job may run 45 minutes; its fuzz smoke alone took 14 of the 30 it had.

Fixed

  • A plane reading the pause file while a writer replaced it, as guardana-control pause add and remove and most editors do, turned the pause state unknown for a poll interval and blocked every call meanwhile. A read that finds the file replaced between judging its name and opening it now starts again, up to three times in all, with every check each time; a link swapped in is still refused and a file replaced at every attempt is still unknown.
  • The release job's image scan pulled every platform of the image by the index's digest, which Docker's default image store refuses for a second platform ("cannot overwrite digest"), so 0.10.1-alpha's release stopped before it attested or published anything. Each platform is now pulled by its own manifest's digest.
  • react gave its whole pass the ten seconds meant for waiting on another writer's lock, so a pass over a list near its bound, judged again before each line, could end with context deadline exceeded while no other writer ran. Each line now waits up to ten seconds for the lock and nothing else is timed. A wait that runs out, or an interrupt, now ends the pass after the lines already written; react prints them and its count line, then exits 1. Once the list refuses a line for its bounds, react names every later finding as not written without taking the lock again, so a long pass over a full list no longer shuts out stops lift.

0.10.1-alpha - 2026-10-09

Tagged and never published: the release job stopped at its new image scan before it attested or published anything. Its changes are listed under 0.10.2-alpha.

0.10.0-alpha - 2026-10-08

One supervised run is now whole. A procedure of schema 0.2 names the resources its steps bind, the exceptions it allows and how a run's children are judged; supervise reports a resource outside the run, a denied action retried in another form and an exception taken, judges a run's tree, and draws one run as a static page. A finding is confirmed only on the named run's own calls, so no run can get another one stopped, and a child run can now be stopped on its own. procedure lint and procedure test check a procedure with cases, and findings export reads the findings log with a cursor. The fixes come from an audit of this release's own changes.

Security

  • Built with Go 1.27.2, which fixes GO-2026-6599, GO-2026-6600, GO-2026-6603, GO-2026-6604, GO-2026-6605, GO-2026-6607, GO-2026-6608 and GO-2026-6610 in crypto/tls, net/http and its HTTP/2 code, html/template, mime/multipart and os; govulncheck found the plane's calls reaching the HTTP/2 ones under 1.27.1.

Added

  • Procedure schema 0.2, read beside 0.1 (ADR-0047). bindings name the resource type each binding holds and binds ties a step or an allowed tool to one; exceptions waive one rule for one step or tool, on a granted approval, a failed step or a reason code; children is inherit, which judges a root run and its whole tree, or separate, which judges one run's own calls and lists its children. A rule that may stop a run is waived only on an approval. A 0.1 document reads as before, with the same digest and the same confirmed findings.
  • Under a 0.2 procedure supervise reports RESOURCE_OUTSIDE_RUN when one binding's calls carry more than one resource, and DENIED_ACTION_RETRIED_ARGUMENTS, _RESOURCE and _AROUND when a policy denial is followed by the same tool with other arguments, another tool or upstream on the same resource (not a read after a denied non-read), or a source's report of the denied tool that no plane call joins. An exception taken raises EXCEPTION_TAKEN, never stronger than the finding it waived. A finding names the run whose call it rests on, a child included, and the report lists the run tree.
  • A child run can be stopped. react writes a stop for a confirmed finding about an open child of the finding's tenant, and a plane refuses that child's next call while its parent and siblings run on.
  • guardana-control findings export writes the findings log with a cursor, in the format guardana.control.findings-export 0.1, up to the last write a report closed (ADR-0048). A log this release creates starts with a header holding a random log_id, which its cursors bind to; an older log is known by its first line.
  • guardana-control procedure lint prints a procedure's id, version, digest, children mode and each rule with its version and whether it may stop a run; procedure test runs a document of cases against it and passes a case only on an exact match (guide).
  • supervise --view <file> draws the run as one static HTML page: the expected steps beside the calls observed, each marked enforced, decided not enforced, observed, exception or approval, blocked or not seen, by shape and line as well as colour. It shows each finding's calls and their neighbours, or with --view-all every call up to a bound (run view).

Changed

  • Every reader of a route (route sign, react, a plane at start, doctor and the stops commands) refuses one that names a rule or a rule version outside the six whose finding may stop a run: REPEATED_DENIAL, STEP_OUTSIDE_PROCEDURE, DEADLINE_EXCEEDED, RESOURCE_OUTSIDE_RUN, DENIED_ACTION_RETRIED_ARGUMENTS and DENIED_ACTION_RETRIED_RESOURCE, each at version 1. Only route sign checked a route's rules before, so a route signed by other means could name any rule.
  • A finding record that carries a run on its event references, a count of references left out, a children mode or a run tree is schema 0.2, and a 0.9 reader refuses it by name. Read a findings log this release writes with this release's notify and react.
  • supervise reads from the runs directory only the run's own tree, so a directory holding more than 1000 runs no longer refuses a supervision.
  • supervise counts a source as heard only from import reports of its descriptor's tenant and project, as coverage does, and bounds each span walk on its own as well as in total. Either can move a finding below CONFIRMED; a changed verdict is a new record, and so a second alert.
  • STEP_OUT_OF_ORDER and CONTINUED_AFTER_FAILURE are version 2. Two proposals of one instant are now untold even within one export, since a plane ships several batches at a time, so a finding that rested on their place in the export is indeterminate. The rule version is part of a finding's id, so supervising a run again writes their findings as new records and alerts again. Neither may stop a run; the six that may stay at version 1, so a route signed before still holds.

Fixed

  • A finding that rests on many events, such as ten thousand denials, was past the log's line bound and refused the whole write. It now cites ten references, the most doubtful first, and counts the rest; its verdict is still weighed over all of them.
  • Under a 0.2 procedure judging a run's tree, one run's calls could confirm a finding against another: a child's denial made the root's later call a confirmed retry, a child's probe of another order confirmed RESOURCE_OUTSIDE_RUN on the root, and a closed child took the tree's REPEATED_DENIAL and deadline. A finding is now confirmed only on the named run's own calls (a retry by a descendant of the denied run included); one that needs another run's call is suspected at most and stops nothing. Each run's deadline is still timed from the tree's first event, which may be another run's.
  • The retry rules turned themselves off past about a thousand denials; they now judge every denial. A tree is bounded at 400 runs, where its report still fits the log's line.
  • DENIED_ACTION_RETRIED_AROUND read as checked with a source never heard, silent or not read, and so did STEP_OUTSIDE_PROCEDURE when a span walk ran out of steps; both read not checked now, and procedure test compares the sources a case expects to be unheard.
  • A rule that is never confirmed could be recorded as confirmed; it is capped.

0.9.0-alpha - 2026-10-07

A confirmed finding can now stop the run it is about. An operator signs a route that says which findings may stop a run and which key lifts a stop, and starts a stop list; after guardana-control supervise, guardana-control react writes a stop for each deterministic, confirmed finding the route allows about an opened run that is still open. A plane configured with the route refuses that run's later calls, and no other run's, and blocks every call while it cannot read or trust the list. A call already running is not cut, and only a lift signed with the route's lift key ends a stop while a plane runs. The refund example shows it on a live plane with two runs. The other changes and fixes come from an audit of 0.8.0, and four of them matter on upgrade. The gateway refuses a configuration file when it, or a directory or link on its path, belongs to an account other than its own or root, when another account or its group may write it, or when it has a second name: a checkout under a umask of 002 needs chmod g-w, and a container's configuration has to be owned by the image's user. An upstream that asks for more input ends the call as failed. A second override of one tool is refused at start. runs open --parent refuses a child whose expiry would pass its parent's.

Added

  • A confirmed finding can stop the run it is about (ADR-0046). An operator signs a route with guardana-control route sign, naming the procedures and rules whose findings may stop a run and the key that lifts a stop, and starts a stop list with stops init. guardana-control react appends a stop for each deterministic, confirmed finding the route allows, about an opened run that is open, and never lifts one; stops lift, signed with the lift key, ends a run's stops, and stops list shows them. A plane configured with the reaction keys checks the route against its own floor at start and reads the list every poll interval: a stopped run's later calls are refused RUN_STOPPED (45) and no other run's, and every call is blocked STOP_STATE_UNAVAILABLE (46) while the list cannot be read, shrinks, is rewritten or does not verify. A call already running is not cut, and a stopped run's children are not stopped. doctor, /healthz and /metrics report the route and the list; examples/refund-supervision/ stops one of two runs on a live plane and lifts the stop.

Changed

  • The policy key and the freshness key, in the configuration and in guardana-control policy renew, are compared as points up to their sign: one private key signs for a point and its negation, so two keys that differ only there were taken as two authorities.
  • An upstream that answers a call, a read or a prompt with input_required, or with input requests of any kind, ends that call as failed, with a fixed answer the gateway does not relay. The library had sent the same call to the upstream again on its own, up to ten times, for the one call the plane decided and recorded.
  • A second override of the same tool on one upstream is refused at start. The last one won, so an effect: READ after an effect: DELETE classified a delete as a read.
  • guardana-control runs open --parent refuses a child whose expiry would pass its parent's.
  • The MCP adapter refuses an obligation that carries a parameter its type does not read, as the gateway already did; a non-advisory one stops the call. The obligations page lists the parameters each type reads.
  • The gateway refuses a configuration file when the file, or any directory or link on its path, is owned by an account other than its own or root, or another account may write it (a sticky directory, or root's on a read-only mount, excepted), and a file with a second name. Its group may not write it either: a checkout under a umask of 002 needs chmod g-w. New are a demo archive that runs without Go, an evidence export another program resumes by cursor, and the documentation on the website. docs/status.md says what is implemented and what is experimental. Nothing here is a security boundary yet.

Changed

  • mode has no default: a configuration that names no enforcement mode is refused at load instead of starting a plane in OBSERVE, which stops nothing its policy decides. Add mode: to a configuration that relied on the default (ADR-0032).
  • The demo's decision point no longer listens on the fixed port 127.0.0.1:18213, so demos run side by side: start the demo with dev --decision-point=silent, which the old command lacks and now needs. dev refuses a system without process groups before it starts anything.

Added

  • A website for control.guardana.dev in site/: one static page with no script and nothing loaded from another host, whose diagrams make docs-gen draws from README's, and the project's mark in the README header (ADR-0030).
  • The documentation on the website: every page, record, the roadmap and the changelog rendered under control.guardana.dev/docs/ by make docs-gen, with links, anchors and diagrams that mean there what they mean on GitHub, and a check that fails when a page and its rendering drift (ADR-0031).
  • A demo archive per platform, guardana-control-demo_<version>_<os>_<arch>.tar.gz, that runs the tutorial and every scenario without Go or a checkout; each release runs its scenarios from the linux/amd64 archive before it is published (ADR-0033).
  • dev --decision-point=silent: a decision point on a port dev binds and never answers, so a rule reading external is undetermined with PDP_TIMEOUT.
  • guardana-gateway trail export: a trail file in a versioned format another program reads, with a cursor to resume from, a record for every line it cannot read, and a trailer; examples/evidence-report rebuilds each call's lifecycle from it without importing the project's internals (ADR-0035).

Fixed

  • A restrict_resources obligation with a prefix let a resource id such as /srv/data/../../etc/passwd, /srv/data/%2e%2e/etc or https://api.example/pub/..?x through; under a prefix, an id holding a segment of dots, an empty segment, a backslash, a %, a ;, a ?, a # or a byte outside printable ASCII is now refused.
  • The plane recorded whatever preview an adapter put on a call's arguments or its result; every event now reaches the sink without previews, as capture is off.
  • A tool result that could not be encoded was recorded as a success with no hash; it is now UNKNOWN, with the protocol status unhashable.
  • An approver's answer succeeded beside a consumed or not-resumed record it could not read; the store now refuses it and takes the answer back.
  • An approver whose answer the plane spent between the approver's write and its check was told the approval had been consumed; it is now told the answer was filed, and any other consumed record still refuses it.
  • The collector kept the argument and result previews another producer sent; it now clears them before the trail file holds an event. A trail file that already holds such an event reads a copy sent again as other content.
  • A pending call told the agent to retry after 0 seconds when approvals.retry_after was under a second; the hint now rounds up to whole seconds.
  • A scenario stopped as one that could not run when the plane's read of its pause file ran late on a busy machine and /healthz briefly reported the pause state stale; the runner now reads it again until its timeout, and any other unknown cause still stops it.

0.2.0-alpha - 2026-09-28

The second release. It fixes how an approval's expiry is kept, how much of the plane a stdio upstream is handed, where a plaintext export may go, and how numbers and uncertain results are recorded. It adds an image of the gateway beside the archives, and pages that say what the plane protects, what it records and which failures it survives. docs/status.md says what is implemented and what is experimental. Nothing here is a security boundary yet.

Added

  • Reason code APPROVAL_STATE_UNKNOWN (44, INDETERMINATE): a lost hold whose approval the plane could not read or trust closes with it, where it closed as APPROVAL_EXPIRED before (ADR-0027).
  • A benchmark of the gateway round trip, and scripts/bench.sh --publish, which records a run from a clean tree, with its hardware and Go settings, in a tracked file under bench/results/ (docs/reference/benchmarks.md).
  • Each release is to publish ghcr.io/guardana/control-gateway:<version> for linux/amd64 and linux/arm64, signed keyless and with build provenance, its digest named in the release notes; RELEASING.md says how to check it and docs/guides/run-in-a-container.md how to run it.
  • A page of the failures the plane is built to survive: the collector, the spool, the decision point, an upstream dying mid-call, the pause file and a restart with calls held, each with a test that runs the built binary against a real failure (docs/reference/failure-modes.md).
  • A threat model and a privacy page: what the plane protects, from whom and where it stops; what a record holds, where it goes and how long it stays (docs/concepts/threat-model.md, docs/concepts/privacy.md).

Changed

  • A stdio upstream no longer inherits the plane's environment. It gets PATH, HOME, LANG, LC_ALL, TMPDIR and USER, each where the plane has it, and the variables its new upstreams.N.env list names; a name under GUARDANA_CONTROL_ is refused, so the exporter's and the decision point's header credentials are no longer handed to it. An upstream that read any other inherited variable starts without it: list each one it needs, and doctor marks a listed name the plane's environment lacks (ADR-0028).
  • export.allow_plaintext admits a plaintext collector on a loopback IP literal only, as pdp.allow_plaintext already did and as ADR-0020 states. A plaintext endpoint on any other host, a name such as localhost included, is refused at start.

Fixed

  • A tool whose definition holds a fractional number, such as "default": 0.7, is fingerprinted and can be classified, and a call whose arguments hold a fraction a double represents exactly is decided. The digest binds a number's value, so 1.0 and 1 digest alike, and every digest of arguments accepted before is unchanged (ADR-0029).
  • A resumed call whose approval expired by the plane's clock before it was handed to the upstream is not sent: it is blocked with APPROVAL_EXPIRED, and the approval stays spent.
  • A call whose answer the gateway could not read, or could not complete over HTTP (a malformed answer, a connection the upstream closed after reading the call, a 429 or 5xx status), is recorded with an UNKNOWN result rather than as the upstream's failure: whether it took effect is unknown.
  • A decision point's answer that reaches the gateway after the call's deadline is a timeout (PDP_TIMEOUT), whatever its status and headers. Such an answer could be read as refused or as unavailable instead.

0.1.0-alpha - 2026-09-25

The first public release. docs/status.md says what is implemented and what is experimental. Nothing here is a security boundary yet.

Added

  • Wire contracts, frozen at 1.0: eight protobuf files for the action envelope, the decision, approvals, results, events, findings, policy bundles and the shared types, with the generated Go. pkg/contract decodes them strictly, refusing unknown fields and undeclared enum numbers, and validates an envelope within stated bounds (ADR-0002).
  • A canonical form for an action and the digest built on it, with golden fixtures (ADR-0005, ADR-0010).
  • Policy documents in agent-policy/v1alpha1, read as strict JSON; bundles signed with Ed25519 over the DSSE pre-authentication encoding; a three-valued matcher where DENY overrides; and the decision kernel with its fixed order and fail-closed table, under which INDETERMINATE never allows a material call (ADR-0012).
  • guardana-control: policy lint, test, keygen and sign; approvals list, approve and reject; pause init, add, remove and list; and console, a page on the loopback that answers held calls and pauses (ADR-0018, ADR-0019, ADR-0023).
  • guardana-gateway, an MCP gateway that decides each call before it reaches the server: run and doctor; the enforcement modes; approvals bound to one action digest and consumed once; obligations; a check that the executed arguments are the authorized ones; evidence kept in a local spool and exported over OTLP (ADR-0013, ADR-0014, ADR-0016).
  • An external AuthZEN decision point that can veto what the signed policy allows, and never grant (ADR-0017).
  • guardana-gateway collect and trail, a trail file without a third-party collector, and GET /metrics in the Prometheus text format (ADR-0020).
  • Run flow: the plane records whether a run took in untrusted input, so a policy's flow rule can block a later send to an untrusted destination (ADR-0021).
  • guardana-gateway scenario run, which holds a live plane to agent-scenario/v1alpha1 files, and guardana-gateway dev, one command for a local plane with its collector and approvals page (ADR-0022, ADR-0023).
  • A demo, examples/vulnerable-mcp-agent, with seven scenarios, and its tutorial.
  • One quality gate, make quality, which CI runs on every push to main and every pull request, and a documentation structure the gate checks (ADR-0015).
  • Release archives for Linux and macOS on amd64 and arm64, with a CycloneDX bill of materials per archive, signed checksums and build provenance (ADR-0025).
  • Governance: DCO sign-off, Conventional Commits, a security policy, a code of conduct, trademark terms and 25 architecture decision records, among them the independence of this project from Guardana (ADR-0024).

Rendered from CHANGELOG.md on main. It describes the tree as it is now; a release's notes say what a tag holds. The latest release is v0.12.0, and its documentation is in its tag.
