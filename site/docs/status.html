Implementation status

What exists in this repository today, component by component. Every other document points here rather than keeping its own list, so this is the only inventory in the project and the one that has to be right.

Components are grouped by what they do, one table per group, and each row gives a stable id, a status and one sentence. The sentence's details link leads to the paths, tests, records and limits behind it.

The product goal is observation across connected agent paths, supervision against procedures and reactions within scoped authority. That complete 1.0 target is planned; control and supervision explains it and the roadmap orders its delivery. The inventory below describes what the alpha can actually do.

In short:

  • What you can do today: put the gateway between an MCP client and its servers and decide each tool call from a signed policy, allowing it, blocking it or holding it for one approval of that exact call. Each decision is recorded with the policy version that made it. An external AuthZEN decision point can veto configured calls without granting authority. A tool outside MCP can ask a plane serving the enforcement API before it acts and enforce the answer itself. You can import runtime traces and an egress proxy's access log as observations, inspect coverage, and check one opened run against its procedure, draw it as a page, hand its findings to a program, and stop that run where a signed route allows it.
  • The limits: the gateway sees only the calls routed through it, the caller's identity comes from its configuration rather than a login, and the evidence trail is not tamper-evident. It is not a security boundary.
  • What to download: the latest release's demo archive runs the demo with no Go and no model key, its platform archive holds guardana-gateway and guardana-control, and the image ghcr.io/guardana/control-gateway holds the gateway. The tutorial starts there.

What the labels mean:

  • implemented: it exists and a command in this repository exercises it.
  • experimental: it exists and can still change without a major version.
  • planned: it is not built. Its details name the path it will take, the record that defines it, or say that no path has been chosen yet. A path that already holds a package doc and a test holds nothing that decides.

Nothing here is a security boundary. Do not deploy it as one.

internal/policykey/ (the private key file and its reader, the public key line and its one parser, the derived key id, the bundle file, and the freshness statement's file, experimental), internal/files/ (create without replacing, replace, bounded read of a regular file), internal/keytext/ (the withholding and quoting both binaries and the approvals page print through, which reads no key), ADR-0018. policy keygen and policy sign write them and the gateway parses policy.public_key through the same package.

policy-matcher

internal/policy/rules/ parses agent-policy/v1alpha1 strictly, internal/policy/bundle/ signs and verifies bundle bytes (Ed25519 over the DSSE PAE); internal/policy/match/ evaluates three-valued; internal/policy/ loads a bundle into a snapshot and installs it in order; ADR-0003, ADR-0012. A holder pinned to the bundle id it serves refuses every other. On a plane a snapshot is confirmed only by a freshness statement bound to its bundle and signed under a key apart from the bundle's, and its serial floor is ordered by serial and then issuedAt (internal/policy/statement.go, floor.go, experimental, ADR-0038); an unconfirmed snapshot decides POLICY_STALE

policy-floor

internal/policystate/. One strict-JSON file per bundle id in an owner-only directory whose marker names a plane's or a signer's kind; raised under the directory's lock against the file's value; Init and Reset are the operator's, and the gateway binary holds neither (ADR-0038). The commands use it (policy renew, policy state init and reset), and so does every plane, through policy.state_dir. A floor protects only while its directory outlives the plane, and an account that can write the directory can lower it

policy-refresh

internal/policywatch/, wired by cmd/guardana-gateway/planepolicy.go, ADR-0038. At start judges the floor, the bundle and the statement: a bundle below or beside the floor, or above it without its statement, refuses the start, and a missing or expired statement starts the plane unconfirmed. Then reads both files every policy.poll_interval, installs a newer bundle only with its statement, refuses and counts every bad replacement without moving the confirmation, and withdraws the confirmation while the wall clock, measured against the monotonic clock, has fallen back more than a second plus 100 parts per million of the time since its highest reading, or reads too far from the first reading to judge, and until a statement issued after that arrives.

A clock reading outside 1970 to 9999, or behind the verified time, the latest issuedAt the plane verified, decides nothing: every call is POLICY_STALE, reads included. /healthz, /metrics and doctor report it. Freshness trusts the plane's clock at start, and the operator schedules policy renew; nothing in the repository schedules it outside dev

external-pdp

ADR-0017. The kernel takes the answer and the policy format reads it (internal/core/, internal/policy/); adapters/authzen/ asks and reads the answer strictly; internal/gateway/ asks only when the answer can change the decision; cmd/guardana-gateway configures it from the pdp. keys, checks its published metadata in doctor and counts the asks on /healthz. The end-to-end tests reach a decision point on the loopback over plaintext; TLS is exercised in the adapter's own tests, against the roots a test hands it, and the command has no setting for a private certificate authority

approval-binding

An approver outside the plane answers through the approval authority below; a hold does not survive a restart, and a plane that keeps a hold journal closes the trail of one it lost at its next start, and counts one it cannot close as left open (ADR-0016)

What it supervises today

The project means to supervise an organization's AI agents (ROADMAP.md). Against that aim, the components above add up to this:

Aim Today
Setup for common agent stacks, a proxy for the rest An MCP proxy; the enforcement API for a tool outside MCP, with a Go and a Python client, which cooperates; one coding runtime's hooks through guardana-control hook; no framework integration and no proxy for other tool APIs
Oversight of what agents do and the data they reach Each tool call, resource read and prompt through one plane is decided, and none runs before its record is written unless the operator let a read run unrecorded; the plane does not see a call that bypasses it, which an imported trace records as testimony and an egress proxy's log as a connection; guardana-control coverage reads the planes' configurations and exports beside it and names a call around the plane, from files, with no plane contacted
Procedures, and deviations from them Policy per call and one flow rule; guardana-control supervise checks one opened run, or a root and its whole tree, against a procedure after the fact, and reports an exception the procedure allows when one is taken; procedure lint reads a procedure as supervise would and procedure test runs it against cases
Attempts to gain access Each refusal the pipeline decides is counted in /metrics, and recorded with its reason codes unless the call's identifiers name no trail, its request id already has an open trail, or the sink refuses one of its events; a request the listener refuses for its origin or its run token is not recorded, and only run token refusals are counted; within one run, supervise reports repeated denials of a tool and, under a 0.2 procedure, a denied action retried with other arguments, through another tool or upstream on the same resource, or around the plane as a source reports it, and the calls of one resource binding that reach more than one resource
Quality: finished, not degraded, nothing skipped A result's status and hash; within one run, supervise reports a skipped step, an order broken and a run that carried on after a failure
Running beside the agents, reporting deviations The plane writes evidence to a spool for export; supervise reads an export when an operator runs it, notify hands its alerts to a program, and findings export writes the findings out for a program that resumes from a cursor; nothing runs on its own
Stopping an agent A pause of every call, of one upstream, of one tool, of one opened run or every run under a root, of one agent or of one principal, for calls not yet running; a stop of one opened run's later calls, a root's or a child's, from a confirmed finding a signed route allows, when the operator runs react; a stop not of a whole tree, nor of one agent or principal
A run drawn as a graph A static page per run from supervise --view: the expected steps beside the calls observed, each marked by shape and line as well as colour; a table, not a graph, and not live
