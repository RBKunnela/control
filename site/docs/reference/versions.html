Format versions

The product is 0.x, with no compatibility promise between minor releases (CHANGELOG.md, ADR-0008), and each format below carries a version of its own. A reader refuses any version it does not read, a new major included, rather than read it as the newest it knows (invariant 3 in AGENTS.md).

The formats

Written is what this tree writes, — where only the operator writes the file. Read is what this tree accepts: 1.x is any minor of major 1, and — means nothing here reads the format back. stable is the frozen v1 wire contract alone; an experimental or alpha format may change without a major version. status.md is the inventory.

The gateway's configuration file and a policy test case carry no version. Each refuses a key it does not know, so a file that names a key a later release added is refused, not read in part. The signed envelopes around a policy bundle, a freshness statement, a route and a lift carry no version of their own, only the payload type each is signed under, and the evidence spool frames its segments with no version at all, so a spool another release wrote is not promised readable. notify's --state list of delivered alerts, one quoted key per line, carries none either.

Which version a plane reads depends on its authority. 0.17 refuses each format 0.18 writes under signed (upgrade a plane).

  • Pause file: 4, naming plane_id, under signed; 2 written and 1 and 2 read elsewhere. A plane refuses 3 and blocks every call, as it does under any unreadable pause file; pause sign alone reads 3 and signs its entries again as 4. 0.17 reads 3 alone under signed, so a 4 file blocks its every call.
  • State backup manifest: 0.2 is written, naming plane_id under signed; any 0.x is read, and a signed restore of a 0.1 manifest, which names no plane, says plane not checked. 0.17 restores 0.2 only where it names no plane, outside signed.
  • Route: reaction-route/v1alpha3, naming plane_id, under signed; v1alpha1 elsewhere. A v1alpha2 route names no plane: the plane, react, stops lift and stops list refuse it, naming route sign, which refuses a v1alpha2 document; stops init --carry reads one only as the route the list it carries was judged under.
  • Stop list: 3.0 under signed, whose header reaction-list-header/3.0 names plane_id; 1.0 elsewhere. A 2.0 list is refused, naming stops init --carry, which alone reads it and carries it into 3.0.
  • Lift: reaction-lift/v1alpha3, naming plane_id, scope and subject, under signed; reaction-lift/v1alpha1 elsewhere. A v1alpha2 lift is read only by a carry.
  • Health answer: schema 3 under every authority. Under stops, health.socket names unheld_entries and unread_entries where 0.17's schema 2 named unheld_runs and unread_runs.

A 1.0 list is not carried into 3.0: start a new list, and react stops again the findings that still may stop a run.

Reading files an older release wrote

  • Wire messages, the evidence export, the runs directory's marker and root states, the hold journal, the spent ledger and the floor directories, a bundle's, a signer's, a trust roster's, a route's, a signed pause file's and a stop list's alike. Any minor of major 1 is read. A member the reader does not know is refused, so a file a later minor extended is refused when that member arrives, never read with it dropped.
  • Approvals directory. Any minor of major 2 is read. A 2.1 record names the authority holding it and the call's tenant and project; a 2.0 record names none of them and is read as held under directory. A 1.0 directory kept the plane's spent mark beside the answers, so it is refused: empty it; its holds expire within approvals.ttl.
  • Run record. Any minor of major 2 is read, except in a signed runs directory's records/, which reads major 3 alone. A record of major 1 names no project, so it is refused, never read as any project's run: open the run again (runs.md).
  • Policy document, scenario, reaction route, freshness statement and lift. One exact kind is read; another is refused, never read as this one.
  • Procedure. A 0.1 document reads as before, with the same digest, rules and findings, and the records it gives keep schema 0.1, unless the report names a source in doubt.
  • Finding log. A log with no header is read as it is; an empty one gains a header when it is opened. A release that does not know a member of a line, such as one reading schema 0.1 alone, or one without sources_in_doubt reading a report that names a source, refuses the whole log as damaged at that line; nothing is misread.
  • Findings export. A cursor holds only in its own log, known by the header's log_id, or by its first line in a log that has no header; the trailer's identity says which.
  • Observation records and the source descriptor. Only the minors in the reader's table are read; another 0.x is refused rather than read as the nearest one. A record is 0.3 exactly when it carries a connection, refusals by reason, callers dropped or its source's kind, and an import report 0.2 exactly when it names runs in doubt or sets every_run_doubted and carries neither. A descriptor is 0.2 exactly when it maps an egress access log, and every 0.1 descriptor keeps its digest. A release whose table lacks a version refuses its lines: 0.14's observe import and coverage refuse a log holding a 0.3 line as damaged. The observation export carries each record's line as the log holds it, so its reader meets 0.2 and 0.3 lines inside an export whose own version stays 0.1; an earlier release's export counts such a line as an unsupported_version gap.

internal/docscheck/versions_test.go holds the table to the constants and readers in the code. It fails when a version changes there, when a format is missing from this page, and, for each reader it can call, when that reader accepts a version the page does not name.
