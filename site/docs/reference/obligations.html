Obligations

An obligation is a condition on a call that proceeds. It travels on a decision in Decision.obligations, under ALLOW_WITH_OBLIGATIONS and under REQUIRE_APPROVAL once the approval is given. A policy rule names an obligation by its type, with string parameters and an advisory flag that is false by default: false means the call proceeds only if the obligation is applied (ADR-0011).

The table below is the catalogue, the closed set of types a policy document may name, with the parameters each type takes and who in this build applies it. Recognising a type is implemented: the parser and policy lint refuse a document naming a type outside it, and the kernel refuses a configuration whose applicable types include one outside it. The gateway rewrites the arguments for its types before the decision it records, and an adapter applies the types it declares to the call it sends. A decision carrying a non-advisory obligation that nothing here applies is DENY with OBLIGATION_NOT_UNDERSTOOD, and no fail-open setting relieves that; an advisory one is skipped.

Checking parameters is implemented: policy lint, policy test, policy sign and guardana-gateway dev refuse a parameter the type does not declare, a required one that is missing, and a value outside the grammar its row states (ADR-0061). A type nothing in this build applies takes no parameters. The first two refusals read rules: a parameter the obligation's type does not declare or requires, at rules[0].obligations[0].params[1].key for a key or at rules[0].obligations[0].params for one missing, and the third rules: a parameter value the obligation's type cannot apply, at rules[0].obligations[0].params[0]: a parameter is named by its position in sorted key order, never by its key or value. policy explain and loading a bundle do not check parameters, so a bundle signed elsewhere still loads and is explained. Its applier reads only the parameters the type declares and parses each value itself, and an obligation it cannot apply as written is not applied: a non-advisory one stops the call and an advisory one is skipped. What is built and what is not is in status.md.
