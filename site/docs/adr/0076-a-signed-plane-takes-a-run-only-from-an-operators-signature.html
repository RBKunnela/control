ADR-0076: A signed plane takes a run only from an operator's signature

Status: accepted Date: 2026-11-06

Amends ADR-0034 under the signed authority of ADR-0073, over the roster of ADR-0071, as ADR-0075 does for the pause.

Amended by ADR-0078: a restore carries the close of every run the backup or records/ names into state/.

Amended by ADR-0079: state/ also holds an empty <id>.seen for each child the plane admitted, and a child without one is refused once its parent's close is carried.

Context

Under ADR-0034 write access to the runs directory is the authority to open and to close a run, and the plane's own account owns that directory. Under approvals.authority: signed that account could open a run, reopen a closed one or move a run under another root by writing a file. A signature stops a forged record; it does not stop the open record being put back after the close that replaced it.

Decision

  • Under signed runs.dir is a signed layout: records/, the operators' account's, which the plane only reads, and state/, the plane's, which no operator command writes. The plane refuses an unsigned directory, refuses to start when its account may write records/ or a directory on its path, and refuses a records/ or a record its own account owns, as ADR-0075 refuses such a pause file.
  • A record there is version 3.0: a DSSE envelope of application/vnd.agent-run-record+json (operators.ActRun, level operate) over a canonical body holding every member of a 2.0 record, the signing key and the absolute path, links resolved, of the records/ it was signed for, which binds it to one path. A copy between two paths counts in neither; planes that use one path on two hosts must differ in tenant or project, or a copy between them counts. A close is a signed record too, which replaces the open one.
  • A record counts only once it names the plane's own records/, its run is of the plane's tenant and project, and the authenticator and the authorizer take it. Any other record, a 2.0 one included, refuses the calls it would cover as unreadable, counted by cause.
  • The replay of an open record after its close is held by the close carried into state/, not by a floor: when the plane takes a closed record, at a call or at its start, it writes the run's close there, and an open record of a run whose close it holds is refused as closed. A close bound to this directory and signed by a roster operator key is carried even once its signer may no longer operate there. A close the plane cannot write is held in its memory and written at its next signed resolve of any run, its start or its stop, whichever finds state/ writable; holding 64, it refuses every signed resolve. A start that cannot carry a close refuses, naming the run. /healthz counts each failed write as carry_failed under runs.signed.
  • The plane makes a root's state and then its lock in state/ at the root's first admitted call; a missing state reads as the start only while its lock is missing too, and blocks the root's calls after.
  • runs open and runs close with --key, --roster and --root-key sign; they verify any record they sign over, a parent's or the one a close replaces, against the roster, the plane's tenant and project (runs close takes them as --tenant and --project) and the directory, refuse one that fails naming why, verify the record they write, and say on standard error what they signed. Without --key they refuse a signed layout.
  • supervise and react read a signed layout as the operator does and take each record only through the roster judge their --roster, --root-key, --tenant and --project make; without all four they refuse it, naming them. A refused record is no run fact: it refuses supervise's input and stops react's pass, naming the record.

Security / compatibility impact

Breaking under signed: an unsigned runs directory refuses the start, so the runs are opened again into a new, empty directory. Nothing changes under memory or directory. state/ is the plane's to write, so its own account can still remove a carried close, and remove a root's state together with its lock, which the next call makes again clean; with both it can undo a close and what the run took in. A close the plane neither resolved nor found at its start can be undone by whoever may write records/. A close state/ did not take protects only the plane that read it: another plane sharing runs.dir takes the open record put back, and so does this one restarted after a crash before the write. supervise and react read records/ without state/, so they do not see a carried close. Records are group-readable, so the plane's account belongs to the records' group.

Alternatives considered

  • A serial floor over the directory: records are written one run at a time, so no single serial orders them, and a floor per run is the carried close.
  • The operator command writing the close into state/: it would need write access to the plane's own state.

Consequences

runs prune removes records only, and the plane's state of a pruned tree stays in state/.

Validation

internal/runs tests each refusal, the replay after a close seen at a call and at a start, a close whose signer lost operate, a state removed after its first call, a record copied from another directory, the operator's judged reads, and prune over the split; internal/runs/signedruns tests both judges against one roster; cmd/guardana-control tests the signed commands and a close over a record of a key the roster lacks, another tenant, project or directory, or unsigned, and supervise and react over a record of a key the roster lacks or of another directory; cmd/guardana-gateway tests the start refusals, the carry across a restart and doctor's counts.
